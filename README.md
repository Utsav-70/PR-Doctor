# PRGuard

A GitHub App that reviews pull requests. When a PR is opened or updated it fetches the
diff and the repository context that matters, runs an LLM reviewer over it, and returns
structured findings.

The design principle everything follows from: **the LLM proposes, deterministic tooling
verifies.** A finding is a hypothesis until something that cannot hallucinate confirms
it. Precision is the metric that matters — a missed bug costs what it would have cost
anyway, but a false positive costs trust in every future comment.

Full documentation is in [`docs/`](docs/) — start with
[`docs/README.md`](docs/README.md).

## Current state

Phase 0 (project setup) and the data layer. The pipeline below is being built as a
vertical slice:

```
GitHub PR → Webhook → FastAPI → Redis/Celery → Fetch diff + context → LLM Reviewer → Structured findings
```

| Piece | State |
|---|---|
| Settings, DB models, migrations | done |
| Compose stack, health checks, Celery app | done |
| `POST /webhooks/github` + signature verification | next |
| GitHub client, diff parser | to do |
| LLM reviewer with structured output | to do |
| Posting comments to the PR | later (Phase 9) |

## Quickstart

```bash
cp .env.example .env          # then fill in the GITHUB_* values
docker compose up --build     # postgres, redis, api, worker
docker compose exec api alembic upgrade head
curl localhost:8000/health
```

Expected:

```json
{"status":"ok","version":"0.1.0","checks":{"database":"ok","redis":"ok"}}
```

Prove the queue path works end to end:

```bash
docker compose exec api python -c "
from apps.worker.tasks import ping
print(ping.delay().get(timeout=15))"
# {'status': 'ok', 'database': True}
```

## Running without Docker

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
docker compose up -d postgres redis     # datastores only
alembic upgrade head
uvicorn apps.api.main:app --reload
celery -A apps.worker.celery_app:celery_app worker --loglevel=INFO -Q reviews,posting
```

## Verifying a change

This project does not carry a test suite, by choice. Instead:

```bash
ruff check . && ruff format --check .
mypy agent db github settings
```

For review quality, set `DRY_RUN=true` and run the pipeline against a real PR — it logs
every comment it would post and posts nothing. Reading that output is more informative
than any unit test would be here.

Three things need a manual look, because nothing above catches them and each fails
silently: diff position mapping, sandbox limits, and prompt-injection framing. See
[`docs/README.md`](docs/README.md) → *Verifying a change*.

## Migrations

```bash
alembic revision --autogenerate -m "what changed"   # review the output by hand
alembic upgrade head
alembic downgrade -1
```

Migrations are autogenerated, then read before committing. Hand-written migrations drift
from the models silently; the check is that `--autogenerate` on a clean database
produces no changes.
